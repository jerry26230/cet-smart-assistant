# 项目改进汇总

截至 2026-09-26，项目已从 Anki 最小插件发展为包含学习资料、计划和三套内置词库的离线备考助手。

## 已完成的改进

| 阶段 | 改进前的问题 | 当前实现 | 验证 |
| --- | --- | --- | --- |
| Task 001 | 尚无插件入口 | 在 Anki 工具菜单注册助手，不修改 Anki 核心 | 首次启动、重复点击、重启后加载 |
| Task 002 | 资料无法持久保存 | 表单校验、按账户存储、原子写入、损坏文件保护 | 保存回读与异常场景测试 |
| Task 003 → 004 | 容易将分项百分比误当成能力强弱 | 得分率只作描述，关注项待确认；默认均衡，可手动选择重点 | 阈值、旧资料兼容及计划规则测试 |
| Task 004 | 学习建议缺少可执行时间分配 | 词汇、听力、阅读、写作翻译的整数分钟计划 | 7200 种时间与重点组合，总时间严格守恒 |
| Task 005 | 助手与 Anki 学习流程割裂 | 创建牌组和正反面卡片，查重、保留原释义、模板冲突保护 | 实机正反面与重复提交验证 |
| Task 005 扩展 | 逐词输入负担大，用户还需自己寻找词库 | 内置四级 3815、六级 5371、雅思 4974 词；选择即可离线建卡 | 全词库数据校验及真实后端 14160 张卡片验证 |
| 批量导入 | 外部词表难以复用 | 文件 / Excel 两列粘贴、编码识别、预览、错误行提示 | CSV 引号、多行、中文编码、大小限制测试 |
| 大批量可靠性 | 逐条建卡会耗尽 Anki 撤销历史 | 使用原生 add_notes 批量写入，合并整批撤销 | 每套一次撤销、重复导入无新增 |

## 核心设计取舍

1. **避免误判专项能力。** 写作与客观题的分布、评分方式不同，绝对得分率不直接用于能力排名；默认均衡覆盖，用户确认后才突出专项。
2. **先让用户能够开始学习。** 内置常用词库为主要入口，批量文件导入和逐词输入用于补充。
3. **依赖 Anki 原有能力。** 卡片、备份、复习调度由 Anki 管理，不修改核心或 FSRS。
4. **保留可追溯来源。** 词库固定版本、SHA256、MIT 授权文件随插件保存。词表为社区参考，不宣称官方完整覆盖。
5. **按学习目标隔离词库。** 三套牌组与笔记类型独立，跨书重叠词各保留一张；同书不重复导入。

## 验证与边界

43 项单元测试通过。真实 Anki 26.9.3 后端验证了三套完整词库的建卡数量、重复导入、整批撤销、卡面生成和新卡状态。Qt 选择框与批量预览做了离屏验证；旧版单词卡流程有实机截图，最新批量界面尚未做桌面截图验收。

尚未实现：专项练习记录、根据学习效果动态调整计划、音频、自动选词与词库进度看板。雅思目前只扩展词汇学习。项目未接入大语言模型，也不提供成绩预测。
